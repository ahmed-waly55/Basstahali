# Angular i18n

The application uses Angular 20's official `$localize` runtime and `loadTranslations`, with Arabic as its source language. Arabic and English share the same URLs. The language button changes language without reloading the document and saves the selection in `localStorage` under `basstahali-language`. Theme selection persists independently.

- Mark text in TypeScript with `$localize` and a stable message ID. Keep message expressions in component initializers or factories; the locale controller recreates the Angular view tree after loading a catalog, while retaining the URL and browser document. Module-level translated strings would become stale because `$localize` evaluates a message when its expression runs and does not automatically reevaluate existing strings. There is no custom translation pipe.
- Run `npm run extract-i18n` after changing source messages. This updates `src/locale/messages.xlf`.
- Update matching units in `src/locale/messages.en.xlf`, preserving named interpolation placeholders such as `SUBJECT` and `PRICE`.
- Run `node scripts/generate-i18n.mjs` to create `public/i118/ar.json` and `public/i118/en.json` from the XLIFF catalogs. These use Angular's Simple JSON format: `{ "locale": "en", "translations": { "messageId": "Text with {$PLACEHOLDER}" } }`. Both JSON files are generated; edit the source catalogs instead.
- The generator uses Angular's official XLIFF 2 parser, preserves message whitespace and placeholders, and fails when IDs or placeholders differ between locales or an English target is missing.
- Run `npm run build` to generate the runtime catalogs and build the application. Build-time localization is disabled (`localize: false`); the browser loads the selected runtime catalog.
- `npm start` serves the application with the same runtime language switch. After editing catalogs, regenerate the JSON files before checking the browser.
- `npm run serve:ssr:basstahali` serves the production application after a build. Server rendering uses Arabic; the browser applies the saved language preference.

API-backed curricula, grades and subjects keep their backend data. Their `nameAr`/`nameEn` fields follow the selected runtime language; they are never added to the static translation catalog.

Vercel serves the browser output and the two static `/i118/*.json` catalogs. Package prices use the browser’s device time zone from `Intl.DateTimeFormat().resolvedOptions().timeZone`: `Africa/Cairo` displays EGP at a fixed rate of 15 Egyptian pounds per dirham; other or unavailable time zones display AED. The same conversion applies to current prices, previous prices and WhatsApp booking messages. This depends on the device’s time-zone setting, requires no location permission and makes no country lookup request. Pricing has no dependency on an IP-country header or a Vercel country Function.
