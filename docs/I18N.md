# Angular i18n

The application uses Angular 20's official `@angular/localize` compiler with Arabic as its source language. Production builds produce Arabic at `/` and English at `/en/`. The language button navigates to the same route in the other locale, preserving query parameters and fragments. Theme selection persists independently.

- Mark text in TypeScript with `$localize` and a stable message ID; use Angular `i18n` attributes for template text where appropriate.
- Run `npm run extract-i18n` after changing source messages. This updates `src/locale/messages.xlf`.
- Update matching units in `src/locale/messages.en.xlf`, preserving named interpolation placeholders such as `SUBJECT` and `PRICE`.
- Run `npm run build` to compile and prerender both languages. Missing translations fail the production build.
- `npm start` serves the Arabic source locale. To serve English during development, use `npm start -- --configuration=en`.
- `npm run serve:ssr:basstahali` serves both production locales after a build.

API-backed curricula, grades and subjects keep their backend data. Their `nameAr`/`nameEn` fields are selected using Angular's `LOCALE_ID`; they are never added to the static translation catalog.

Vercel serves localized browser output and the separate `/api/visitor-country` Node Function. Imports in that Function use JavaScript extensions so Vercel's emitted ESM runs correctly. Country responses must remain private and uncached because prices depend on each visitor's hosting-provided country header.
